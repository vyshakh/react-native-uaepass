# react-native-uaepass example

An [Expo](https://expo.dev) (SDK 57) app that uses the library straight from this repository — its source (`../src`), its native code, and its Expo config plugin (`../app.plugin.js`).

`ios/` and `android/` are generated by `expo prebuild` and are not committed, so every build exercises the config plugin the same way a consumer's app does.

## Setup

From the repository root:

```sh
yarn
cp example/.env.sample example/.env   # then fill in your UAE PASS client
```

`example/.env` drives both the native config (URL scheme and callback hosts, via the config plugin in `app.config.ts`) and the values passed to `UAEPass.login()` in `src/App.tsx`.

## Run

```sh
yarn example ios       # expo run:ios
yarn example android   # expo run:android
```

Both run `expo prebuild` automatically the first time. After changing `.env`, `app.config.ts` or the config plugin (`../plugin`), regenerate the native projects:

```sh
yarn example prebuild  # expo prebuild --clean
```

Changes to the library's JavaScript (`../src`) hot-reload; changes to its native code (`../ios`, `../android`) need a rebuild.

Expo Go can't load this app — it contains custom native code.

## How the library is wired in

The library is the repository root, so it can't be an npm dependency of this app (Yarn won't symlink a package into its own subdirectory). Instead:

- `react-native.config.js` autolinks it from `..`
- `metro.config.js` bundles `react-native-uaepass` from `../src` and blocks the root's own `react` / `react-native` dev copies so only one of each is loaded
- `app.config.ts` loads the config plugin from `../app.plugin.js`
